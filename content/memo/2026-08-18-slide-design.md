## ここから学ぶこと（自分向けの結論）

- **「テキストで一括生成 → 全部作り直し」がデザインが下手に見える原因**。部分修正が効かないので、直すたびに全体が崩れる。
- 対策は**「見た目そのものを直接いじれる形式」で持つこと**。具体的には次の2択。
  - **A. SVG を直接編集**：スライド1枚 = 1 SVG。座標・色・フォントサイズだけをピンポイントで書き換えられるので、「ここだけ変えて」が本当に「ここだけ」で済む。課金もツール依存もなし。
  - **B. Figma をブラウザで操作**：見栄え重視の営業資料向け。ただし **Figma MCP は重い＆無料枠をすぐ食う**ので、MCP ではなくブラウザ操作で触らせる。
- **Marp（Markdown → HTML/PDF）は「速いが凡庸」**。社内メモや手順書には十分だが、**お客様に出す提案資料には弱い**。使い分ける。
- 迷ったら：**中身を固める段階は Markdown、見せる段階は SVG**。

## このリポでの当面の運用

- 提案資料・セミナー資料・記事内の図版は、**まず SVG で1枚ずつ作る**（`articles/` の既存ページも SVG を使っているので相性が良い）。
- 修正依頼は「**この要素のこの属性だけ**」の粒度で出す。作り直しをさせない。
- PDF が必要なものは、SVG → HTML にまとめてブラウザ印刷で PDF 化（`shiryo/` の配布物と同じ流れ）。
- Figma を使うのは、**外に出す見栄え重視の資料に限定**。使うときも MCP ではなくブラウザ操作。

## 追記4（2026-08-19）：なぜ「Claudeがログインすれば解決」にならないか

実測した結果、**壁は認証ではなくネットワーク**だった。

| 試したこと | 結果 |
|---|---|
| Web検索でテンプレ名・URLを探す | ✅ できる（サーバー側の検索なので制限を受けない） |
| `www.figma.com` / `api.figma.com` を開く | ❌ 403（egress proxy のポリシー拒否） |
| `google.com` / `dribbble.com` など画像ホスト | ❌ 同様にブロック |
| `github.com`・パッケージ管理系 | ✅ 通る |

つまり claude.ai/code のこの環境は**GitHubとパッケージ管理系以外、外に出られない**。
ログインは「あなたは誰か」を解く鍵で、ここで閉じているのは「そもそも到達できるか」。**別の壁なので鍵では開かない。**

**パスワードは渡さない／受け取らない。** 仮に渡されても上記の理由で使えないし、預かるべきものでもない。

到達可能にしたい場合の正攻法は次の2つ：

1. **環境のネットワークポリシーで `figma.com` を許可する**（claude.ai/code の環境設定）。
   その上で **Figma のパーソナルアクセストークン**（パスワードではない・スコープ付き・いつでも失効させられる）を渡せば、REST API 経由でファイルを読める。
   ただし **Community のファイルは API から直接は読めない**。いったん自分のドラフトに複製してからでないと対象にならない。
2. **Mac でローカルの Claude Code を動かす。** ネットワーク制限がないので、ブラウザ操作で直接見に行ける。Tak が Codex でやっているのはこの形。

当面は「Claude がリンクを出す → 佐藤さんが開いて選ぶ → スクショか判断を渡す」が最短。

## 追記5（2026-08-19）：本人の要望 ―「オシャレなデザイン」「UI」「パワポ資料」も欲しい

本人の言葉：**「めっちゃオシャレなデザインも欲しい。UIも。パワポ資料も」**

現時点では**要望として記録するだけ**。着手は別途指示を待つ。3つは別物なので、必要になったら下の区別で進める。

### 1. オシャレなスライド

- 今の `content/slides/` の型は**わざと「堅実」寄り**（明るい背景・青・落ち着いた余白）にしてある。会社案内・提案書向け。
- 本人が「オシャレ」と言っているのは、Figmaで見ていた **Free Grey Pitch Deck** 系統。
  **黒背景・特大の見出し・差し色1色（オレンジ）・数字を大きく見せる**路線。
- 対応：**堅実版を消さず、濃い版（dark）のテンプレを別途追加する。** 用途で使い分ける。
  - 堅実版 … 提案書・見積・行政や金融が相手
  - 濃い版 … セミナー・登壇・対外プレゼン

### 2. UI デザイン

- アプリ・デモ画面のモック。`index.html` の `:root` トークンがそのまま使えるので、配色とフォントは流用できる。
- **何の画面を作るかが決まっていない。** 着手前に対象を確認すること（既存の `demo/` 配下の画面か、新規か）。

### 3. パワポ資料（.pptx）

- **ここだけ技術的に別物。** SVG では `.pptx` にならない。
- 判断基準：
  - **相手に編集させる必要がある** → `.pptx` で書き出す必要あり（生成は可能）
  - **見てもらう・配るだけ** → PDF で足りる。SVG → HTML → 印刷で出せる
- 「パワポで」と言われたら、まず**どちらなのかを確認**する。編集不要なら PDF の方が崩れない。
