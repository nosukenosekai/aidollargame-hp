# メモ：スライド・図版のデザインを底上げする作り方（2026-08-18）

> きっかけ：「毎回デザインが下手」という自覚があるので、これを機にやり方を変える。
> 出典：X の @RealtyPnw（Tak）のポスト（2026-08-18 12:56・21万表示）と、その返信スレッド。

## スレッドの要点

1. **Tak（元ポスト）**
   これまでは ChatGPT に HTML かパワポでスライドを作らせていたが、**Figma を直接いじらせると圧倒的に作りやすい**。もっと早くやればよかった。

2. **Tak（補足）**
   ただし **MCP コールはすぐ Figma の無料利用リミットに達する**。コツは **Figma をブラウザ上で Codex に操作してもらうこと**。

3. **Naoko Manchun Milky Naomi（返信）**
   自分は **Markdown で書かせて → Marp で HTML を吐かせる**のを Claude Code 上でやっている。Figma は MCP が重い印象。ただしエンジニア向けではなく **fancy なプレゼン**を作るなら話は別かもしれない。

4. **Tak（返信）**
   MCP が重い（Figma もいずれ課金が必要になる）ので、**Codex にブラウザ上で SVG を直接いじってもらっている**。自分もずっと Markdown → HTML だったが、それだと**「ここだけ変えて」の指示のはずが Claude / Codex ともに結構よけいな所まで変えてくる**。ブラウザ操作なら**指示が一番的確に処理される**し、スライドとしての見栄えもとてもいい。

## ここから学ぶこと（自分向けの結論）

- **「テキストで一括生成 → 全部作り直し」がデザインが下手に見える原因**。部分修正が効かないので、直すたびに全体が崩れる。
- 対策は**「見た目そのものを直接いじれる形式」で持つこと**。具体的には次の2択。
  - **A. SVG を直接編集**：スライド1枚 = 1 SVG。座標・色・フォントサイズだけをピンポイントで書き換えられるので、「ここだけ変えて」が本当に「ここだけ」で済む。課金もツール依存もなし。
  - **B. Figma をブラウザで操作**：見栄え重視の営業資料向け。ただし **Figma MCP は重い＆無料枠をすぐ食う**ので、MCP ではなくブラウザ操作で触らせる。
- **Marp（Markdown → HTML/PDF）は「速いが凡庸」**。社内メモや手順書には十分だが、**お客様に出す提案資料には弱い**。使い分ける。
- 迷ったら：**中身を固める段階は Markdown、見せる段階は SVG**。

## このリポでの当面の運用

- 提案資料・セミナー資料・記事内の図版は、**まず SVG で1枚ずつ作る**（`articles/` の既存ページも SVG を使っているので相性が良い）。
- 修正依頼は「**この要素のこの属性だけ**」の粒度で出す。作り直しをさせない。
- PDF が必要なものは、SVG → HTML にまとめてブラウザ印刷で PDF 化（`shiryo/` の配布物と同じ流れ）。
- Figma を使うのは、**外に出す見栄え重視の資料に限定**。使うときも MCP ではなくブラウザ操作。

## 追記（2026-08-19）：資料は毎回 Figma を参考にしてから作る

本人指示：**「これから資料を作るときは毎回 Figma を参考にして」**。運用ルールとして `CLAUDE.md` に反映済み。

背景として整理したこと：

- **Figma がオシャレなのではなく、Figma に乗っているものがオシャレ。** 効いているのは主に**コミュニティのテンプレート（＝プロが作った型）**で、オートレイアウトやマウス操作は作業効率の話。
- **Figma の書き出しも結局 SVG。** 表現力の差ではないので、型さえ借りれば SVG 制作でも同じ見栄えになる。
- 「毎回デザインが下手」の正体は、**毎回ゼロから配色とフォントサイズを決め直していること**。型を固定すれば構造的に起きなくなる。
- スレッドの Tak 本人も、最初は「Figma 直接」と言いつつ、最後の返信では **MCP の重さと課金を理由に「ブラウザ上で SVG を直接いじる」に着地**している。参考にするのは Figma、作るのは SVG、という切り分けはこれと同じ。

制約：**Claude はこのリモート環境から Figma にログインできない。** よって分担は「**参考テンプレを選ぶ／スクショを渡すのは佐藤さん、SVG に落として作り込むのは Claude**」。
